# Architecture (deep dive)

Full architectural reference for the PHP SDK. CLAUDE.md carries the compact summary and the load-bearing "do NOT" directives; this file holds the detail, rationale, and historical notes behind each.

- **Namespace root:** `CNIC\` mapped to `src/` (PSR-4)
- **Shared abstracts (in `CNIC\`):**
  - `AbstractClient` — shared foundation for all registrar API clients; owns the `request()` lifecycle as a template method (`performRequest()`), so subclasses provide only the `buildCommand()`/`newResponse()` hooks, a thin `request()` wrapper, the default logger, and the SocketConfig subtype
  - `AbstractSocketConfig` — shared base for all SocketConfig classes; subclasses provide `getPOSTDataParams()` and their own `$parameters` array
  - `HttpTransport` — extracted cURL layer; owns the cURL handle lifecycle and exposes `post()` (single request) plus `close()` (release the handle)
  - `AbstractResponseTemplateManager` — shared template container plus its concrete `addTemplate()`/`getTemplates()`/`hasTemplate()`/`isTemplateMatch*()` operations; subclasses redeclare their `$templates` array and supply the abstract hooks — `getTemplate()` (fetch/build one template), `generateTemplate()` (wire format), `createResponse()`, `parseResponse()`, and `matchKeys()` (the two compared hash keys: `CODE`/`DESCRIPTION` for CNR, `status`/`message` for IBS)
  - `AbstractResponseTranslator` — shared `translate()`/`findMatch()`/`replacePlaceholders()` pipeline; subclasses supply narrow hooks — `templates()` (the brand's template container), the two rewrite maps (`descriptionRegexMap()`/`descriptionRawPatternMap()`), `fieldName()` (`description` for CNR, `message` for IBS), and `hasMissingRequiredFields()` (the invalid-template fallback trigger: `CODE`/`DESCRIPTION` for CNR, `status` for IBS). Placeholder stripping is unified on a per-field callback (only inside the human-readable field), **not** global — so `{UPPER}` content in other data fields is preserved. (Ref: RSRMID-2893.)
  - `AbstractResponse` — shared foundation for all registrar Response classes; owns the constructor skeleton (template method), command sanitisation, column/record bookkeeping (`registerColumn()`/`addRecord()`), record-cursor navigation and the derived pagination getters. Subclasses supply the wire hooks (`translate()`/`populate()`), the record factory (`newRecord(): RecordInterface`), the status/code accessors (`getCode`/`getDescription`/`isError`/`isSuccess`) and the pagination primitives (`getCurrentPageNumber`/`getFirstRecordIndex`/`getLastRecordIndex`/`getRecordsTotalCount`/`getRecordsLimitation`/`hasNextPage`/`hasPreviousPage`) that read brand-specific columns/status. Implements the core `ResponseInterface` only — the CNR-only capabilities are **not** here (see `ExtendedResponseInterface`). (Ref: RSRMID-2904.)
  - `AbstractRecord` — shared foundation for all registrar Record classes; holds all record behaviour (`getData()`/`getDataByKey()`), since record data has one shape (`array<string,mixed>`) across brands. `CNR\Record` and `IBS\Record` are empty markers extending it, instantiated by each Response's `newRecord()` hook. (Ref: RSRMID-2904.)
  - `System` enum — string-backed `OTE`/`LIVE`; the API system a client is on. `AbstractClient` holds it as `protected System $system` (default `LIVE`); `useOTESystem()`/`useLIVESystem()` set it, `isOTE()` and `getSystem()` read it. The public bool `isOTE()` API is preserved — the enum only replaces the internal `bool` flag. (Ref: RSRMID-2896.)
- **Inheritance chain:**
  - `CNR\Client` and `IBS\Client` both extend `AbstractClient` directly; `CNR\Client` additionally `implements RoleCredentialsInterface` (the CNR-only role-login seam — see the client-contract-segregation bullet)
  - `MONIKER\Client` extends `IBS\Client` — Moniker and IBS share the same API platform; only their `SocketConfig` (endpoints/credentials) differs. Not `final`, deliberately (see the RSRMID-2920 decision record below)
  - `CNR\SessionClient extends CNR\Client` and uses the `SessionCapable` trait for login/logout. It is the **only** SessionClient: IBS and Moniker had empty `SessionClient` subclasses named after a lifecycle their platform does not have, deleted in RSRMID-2920 — `ClientFactory::ibs()`/`moniker()` return the brand `Client` instead
  - `CNR\SocketConfig` and `IBS\SocketConfig` extend `AbstractSocketConfig` directly; `MONIKER\SocketConfig extends IBS\SocketConfig` (mirroring `MONIKER\Client extends IBS\Client`), reaching `AbstractSocketConfig` transitively
  - `CNR\Response` and `IBS\Response` both extend `AbstractResponse` as **siblings** (neither is-a the other); `CNR\Record` and `IBS\Record` both extend `AbstractRecord` as siblings. MONIKER has no Response/Record of its own — it reuses IBS's.
- **IBS and CNR are siblings, not parent/child:** `IBS\Response` and `CNR\Response` both extend `AbstractResponse`; `IBS\Record` and `CNR\Record` both extend `AbstractRecord`. Each brand adds only its parsing/status/pagination differences on top of the shared base. `IBS\Column` is a **standalone** implementation (does not extend `CNR\Column`) because IBS JSON responses carry mixed-typed values (strings, nested objects, lists) that CNR columns do not. (Historical note: IBS previously extended `CNR\Response`/`CNR\Record` directly and threw `UnsupportedFeatureException` from 5 inherited CNR-only methods — a refused-bequest smell removed in RSRMID-2904 by pulling the shared machinery up into `AbstractResponse`/`AbstractRecord` and segregating the interface.)
- **Response construction is a template method:** `AbstractResponse::__construct()` defines the skeleton and delegates the brand-specific steps to protected hook methods — `translate()` (raw-response translation), `populate()` (parse + record assembly) and `newRecord()` (record factory). Both `CNR\Response` and `IBS\Response` implement those hooks (each marked `#[\Override]`) to plug in their own `ResponseParser`/`ResponseTranslator`, PROPERTY-vs-flat-JSON handling and Record type. When adding a new brand or changing how a response is parsed, implement the hooks — do not reimplement the constructor.
- **The pagination seam is deliberately asymmetric — derived getters on the base, primitives per brand (do not "simplify" it):** `AbstractResponse` implements the 5 getters that are pure functions of the primitives (`getNextPageNumber`/`getNumberOfPages`/`getPagination`/`getPreviousPageNumber`/`getRecordsCount`) and leaves the 7 primitives (`getCurrentPageNumber`/`getFirstRecordIndex`/`getLastRecordIndex`/`getRecordsTotalCount`/`getRecordsLimitation`/`hasNextPage`/`hasPreviousPage`) to each brand. RSRMID-2912 proposed hoisting single-page defaults for the 7 onto the base and deleting IBS's overrides; it was **declined** and is now closed as **Cancelled** (deliberately not "Done" — the refactor was never implemented, and a Done record would assert the opposite of what shipped). **This entry is therefore the authoritative decision record**, not the Jira issue: it is the reason the rationale below is written out in full here rather than left in a ticket. RSRMID-2918 is the live issue that corrected the docblock and added the guard.
  - **The premise it was built on was wrong.** The old class docblock claimed the primitives "remain abstract here", which reads as *`AbstractResponse` declares them `abstract`*. It does not — the only members it declares abstract are the three protected hooks `translate()`/`populate()`/`newRecord()`. The 7 are plain `ResponseInterface` methods the base simply never implements; reflection reports them as abstract members of `AbstractResponse` purely because it implements that interface, with `getDeclaringClass()` still pointing at `ResponseInterface`. The docblock was corrected in RSRMID-2918 so the same refactor is not proposed again off the back of it. Two corollaries, since RSRMID-2918 itself asserted otherwise and the mistake is easy to repeat: (a) "not abstract" is true only in the sense that matters — `AbstractResponse` declares nothing, though the methods *are* abstract by virtue of the interface, which is why reflection lists them; (b) `addColumn` is **not** wrongly grouped with them — it is in exactly the same category (interface-declared, unimplemented on the base, supplied per brand at `src/CNR/Response.php` / `src/IBS/Response.php`), so do not "fix" the docblock by removing it from that list. What separates `addColumn` and the status/code accessors from the 7 primitives is only that the no-defaults rule below is specific to pagination.
  - **Failure mode the seam prevents: a silent wrong answer.** Today a brand that forgets pagination cannot be instantiated — PHP raises a declaration-time fatal for the unimplemented interface methods. With base defaults it would instead quietly report "page 1 of 1, no next page", and a consumer paging a list would lose pages 2..N with no error anywhere. Trading a loud compile-time error for a silent data-loss default is the wrong direction, and the saving was 6 one-line bodies — not the ~60 lines the ticket claimed, since most of IBS's block is the load-bearing `getLastRecordIndex()` docblock plus its real `count - 1`-or-`null` logic (the fix for a `LAST = -1` underflow on empty lists).
  - **A `SinglePageResponse` trait was also rejected**, despite the `CNR\SessionCapable` precedent for traits in this codebase: there are only two Response implementations (MONIKER reuses `IBS\Response` verbatim), so any base default *or* trait would serve exactly one consumer — speculative generality. Revisit only if a third genuinely non-paginating brand arrives.
  - **Erosion is CI-guarded, and only reflection can do it.** `tests/ResponsePaginationSeamTest.php` asserts each brand declares all 7 itself, that the base's declaration of them still belongs to `ResponseInterface`, and that the 5 derived getters *are* on the base. A structural test is not a stylistic choice here: the refactor is behaviour-preserving (base defaults would return exactly what IBS returns today), so no behavioural test can detect it. Verified by doing it — with a `getCurrentPageNumber()` default hoisted onto the base and IBS's override deleted, the seam test failed (2 of its 3 methods) while the **entire rest of the suite stayed green**: 339 passed, 0 failed. If you repeat that experiment, note that `.github/phpunit.xml` sets `stopOnDefect="true"`, so a plain `composer test` halts at the first failure and leaves the rest pending — to observe the "nothing else fails" half you must run the suite with the seam test temporarily set aside (or flip that flag). (Ref: RSRMID-2912 declined, RSRMID-2918.)
- **Record/column construction is factory-hooked, but the two use opposite hook shapes because the types allow only that:** `AbstractResponse::addRecord()` delegates to an abstract protected `newRecord(array $h): RecordInterface` **output** hook — each brand implements it to build its own Record (`CNR\Record` / `IBS\Record`). Records work as an output factory because both brands share one shape (`array<string,mixed>`). Columns **cannot** use that shape: `CNR\Column` takes `string[]` while `IBS\Column` takes mixed JSON values, so a param-typed `newColumn(string, array): ColumnInterface` factory can't stay type-clean under PHPStan L9 / Psalm L1 — the base factory would have to narrow `array<array-key,mixed>` into CNR's `string[]` constructor, which both analysers reject (`argument.type` / `MixedArgumentTypeCoercion`) and the toolchain forbids silencing. The bookkeeping is instead de-duplicated the **other way round**: each brand's `addColumn()` builds its own correctly-typed Column locally and hands the finished instance to a shared `AbstractResponse::registerColumn(ColumnInterface $col): static` helper that owns the `$columns`/`$columnkeys`/`$columnindex` bookkeeping once. So the input to the shared step is polymorphic (a constructed column), not a param-typed factory. Don't try to "symmetrise" columns onto a `newColumn()` factory like records — it is infeasible under strict analysis; keep the `registerColumn()` shape. (Ref: RSRMID-2899, superseding the RSRMID-2898 note that left `addColumn()` fully duplicated.)
- **Core vs. extended Response contract (interface segregation):** `ResponseInterface` is the **universal** contract every brand fully supports. The richer capabilities of the CNR-class API — telemetry (`getQueuetime()`/`getRuntime()`), transient/pending status (`isTmpError()`/`isPending()`) and the table-friendly `getListHash()` — live on `ExtendedResponseInterface extends ResponseInterface`, implemented **only** by `CNR\Response`. IBS/Moniker responses implement the core interface only, so those 5 methods are simply **absent** there (not present-and-throwing). `AbstractClient::request()` returns the core `ResponseInterface`; a consumer holding that shared type must narrow via `instanceof \CNIC\ExtendedResponseInterface` before calling any of the 5. Consumers holding the concrete `CNR\Client`/`CNR\Response` are unaffected — `CNR\Client::request()` returns the concrete `CNR\Response`, which has everything. Do **not** re-add the 5 to the core interface. (Ref: RSRMID-2904.)
- **An interface declaration must match its implementation, and must not describe construction (RSRMID-2918).** Two drifts had accumulated on `ResponseInterface`, both fixed in v20.0.0. They share one root cause — the interface was edited independently of the class implementing it — but they resolve in *opposite* directions, which is the instructive part:
  - **`getColumnKeys()` — widen the interface to match the implementation.** The interface declared `getColumnKeys(): array` while `AbstractResponse` has always implemented `getColumnKeys(bool $filterPaginationKeys = false): array`. Because this project mandates typing against the interface, the pagination-stripping capability was **unreachable to exactly the consumers told to depend on it**: the call ran fine, but PHPStan/Psalm rejected it with `Method CNIC\ResponseInterface::getColumnKeys() invoked with 1 parameter, 0 required`, leaving only bad workarounds (retype to `CNR\Response` and lose brand-neutrality, or silence the analyser). Widening the interface is **breaking** for direct implementers (they must add the parameter), hence the major bump; callers are unaffected because `false` is the default. General rule: when a parameter is added to an implemented method, add it to the interface **in the same change**.
  - **`__construct()` — delete it from the interface instead.** It declared 3 parameters (`$raw, $cmd, $ph`) against `AbstractResponse`'s 4 (`$context` was added for custom loggers). Syncing it would have been the wrong fix: PHP **exempts constructors from signature-compatibility checks**, so the declaration constrained no implementer — which is precisely why this drift could persist silently, where the `getColumnKeys()` one at least produced a hard analyser error. Nothing constructs through the interface either: responses are built by the brand factory hooks `AbstractClient::newResponse()` and `AbstractResponseTemplateManager::createResponse()`, each instantiating its own concrete `Response`. So construction is already the factories' concern and the interface is the wrong place to describe it; what remains is a contract about what a response can be *asked*. Removal only relaxes the contract, so no implementation stops satisfying it — verified: instantiating via `class-string<ResponseInterface>` with 3 or 4 args analyses identically before and after. The single externally observable effect is reflective: `(new ReflectionClass(ResponseInterface::class))->getConstructor()` now returns `null`.
  - **Both are guarded by `tests/ResponseInterfaceConsumerTest.php`, and neither could be guarded behaviourally** — the same lesson as the pagination seam above. For `getColumnKeys()` the test makes its calls on `ResponseInterface`-typed variables, so PHPStan L9 / Psalm L1 (which analyse `tests/`) fail `composer lint` if the signature narrows again; before the fix the interface was wrong and all 342 tests passed. For `__construct()` the guard is a reflection assertion, because PHP will never flag a re-add. To find this defect class again, compare `getNumberOfParameters()` of every interface method against each implementation — a throwaway reflection script over `src/`'s interfaces surfaced both in seconds.
- **Transport tuning is the caller's decision, not a brand default (RSRMID-2915, breaking in v20.0.0).** `IBS\Client` used to override `getDefaultCurlOpts()` to return `[CURLOPT_IPRESOLVE => CURL_IPRESOLVE_V4]`, forcing IPv4 name resolution on every IBS/Moniker integration. It was a workaround for a handful of customers whose hosts misbehaved over IPv6, and the library has since been shown to work without it. The override is removed: one environment's networking problem is the wrong thing to hard-code into everyone's transport, and picking a resolution mode is a caller concern. Affected integrations opt in with `setExtraCurlOptions([CURLOPT_IPRESOLVE => CURL_IPRESOLVE_V4])` — the public API added in RSRMID-2913, which was deliberately the first step of this cleanup so the escape hatch existed before the default was withdrawn.
  - The `getDefaultCurlOpts()` hook itself **stays**, even with zero overrides: `resetCurlOptions()` is defined in terms of it (restoring defaults rather than blindly wiping the bag), and a genuinely protocol-mandatory option could still justify one. A default that merely papers over one environment's networking does not — do not re-add one. Guarded by `AbstractClientCurlOptionsTest::testNoBrandOverridesTheDefaultCurlOptsHook()`, which asserts all three brands resolve `getDefaultCurlOpts()` to `AbstractClient`.
  - Note the consequence for migrating callers: an opted-in option is *caller* state, so `resetCurlOptions()` discards it and it must be set again — whereas before, IPv4 survived a reset as a brand default.
- **The caller wins on cURL options, except on a closed set the transport owns — and rejection is loud (RSRMID-2919, breaking in v21.0.0).** `setExtraCurlOptions()` used to be a half-truth: the value landed in the client's `$curlopts` bag (so introspection and the unit tests looked right) and was then dropped one layer down, because `HttpTransport::post()` did `curl_setopt_array($h, [transport defaults] + $options)` and PHP's `+` keeps the **left** operand on a duplicate key. Eleven keys never reached the wire — a caller asking for a 5s timeout silently got 300s. The operands are now swapped (`$options + [defaults]`), so the caller wins, and the keys that must not be caller-controlled are rejected instead of ignored.
  - **Why not simply swap the operands.** The 11 colliding keys were three different things, and only one of them was a defect. *Envelope invariants* — `CURLOPT_URL`, `POST`, `POSTFIELDS`, `RETURNTRANSFER`, `HEADER` — must stay unoverridable or response parsing breaks (`RETURNTRANSFER => 0` makes `curl_exec()` return `true` and the parser gets nothing). *Security posture* — `SSL_VERIFYPEER`/`SSL_VERIFYHOST` — was protected only by accident, but the protection is real and worth keeping deliberately: a generic convenience bag is the wrong place to disable certificate verification. *Legitimate tuning* — `TIMEOUT`, `CONNECTTIMEOUT`, `HTTPHEADER`, `USERAGENT` — is where the actual bug was, and those are now caller-overridable.
  - **The protected set is `HttpTransport::PROTECTED_OPTIONS`** (public, so consumers and tests can read it) and passing any of them raises `UnsupportedFeatureException` naming the offending constants, before the handle is touched — a rejected option is a programming error, not a network event, and must not cost a request. Silence was the whole defect; do **not** downgrade this to an ignore. Pinned by `HttpTransportCurlOptionsTest::testProtectedOptionsAreExactlyTheEnvelopeAndTlsKeys()`: widening the list silently re-breaks legitimate tuning, narrowing it gives away one of the two guarantees, so either direction has to be a deliberate edit.
  - **`CURLOPT_HTTPHEADER` is additive, and the transport's own lines are protected too.** Caller lines are appended; restating one of the transport's four (`Expect:`, `Content-Type`, `Content-Length`, `Connection`) throws, matched case-insensitively on the field name. This is the header-level twin of `PROTECTED_OPTIONS` and follows from it: `Content-Type`/`Content-Length` are derived from the POST body and `Connection` from the reused handle, so overriding one corrupts the request exactly as overriding `CURLOPT_POSTFIELDS` would — and a wrong `Content-Length` fails *silently*, which is the defect class this ticket closed. Replacing wholesale would drop the transport's entries; appending blindly would put two `Content-Type` lines on the wire and leave the winner to the server; so a collision is an error rather than a merge. A non-array `CURLOPT_HTTPHEADER` is deliberately left in `$options` for cURL to reject with its own `TypeError` (verified: `curl_setopt_array()` raises before `curl_exec()`, so nothing is sent) — dropping it quietly would be the wrong lesson to draw from this ticket.
  - **The timeout gap is closed separately, and was additive:** `AbstractClient::setSocketTimeout()`/`getSocketTimeout()` delegate to `AbstractSocketConfig`. Before this there was **no** supported way to change the request timeout — the property is protected with only a getter, the SocketConfig has no public accessor on the client, and the `CURLOPT_TIMEOUT` route was the one being discarded. Both routes now work; the bag wins on collision, because the transport applies the caller's options over the timeout the client hands it. (Note for archaeologists: v20.0.0's docs briefly named a `setSocketTimeout()` that did not yet exist — corrected in `1838c76`, then made true here.)
  - **A negative timeout is rejected at the setter,** via the new `CNIC\Exception\InvalidConfigurationException` (additive, extends `CnicException`, so `catch (\Exception)` consumers are unaffected). Not gold-plating: verified on PHP 8.3.31 that `curl_setopt($h, CURLOPT_TIMEOUT, -5)` returns `false`, and `HttpTransport` does not inspect `curl_setopt_array()`'s return, so a negative value would have been dropped with no signal — the same silent divergence, reintroduced by the very setter added to end it. The new exception type is for *configuration values out of range*, as distinct from `UnsupportedFeatureException` (capability absent); reuse it rather than reaching for a bare `\Exception` next time a setter needs a guard.
  - **The test that let this through is the lesson.** `AbstractClientCurlOptionsTest::testSetExtraCurlOptionsMergesOverTheBag()` asserted the bag and passed throughout, for two releases, while half the options it described were being discarded. Assertions about transport behaviour have to observe the *effective* arguments: `tests/HttpTransportCurlOptionsTest.php` covers the rejection guard offline, `tests/Functional/HttpTransportTest.php` proves the merge over a loopback socket (a stalling endpoint plus a 1s caller timeout — asserting the effect, not the option value), and `CNICTEST\Support\SpyTransport` records what the client hands the transport. "In the bag" is not "on the wire".
- **Client contract segregation (the client-tree twin of the Response one):** `AbstractClient` used to be a CNR base wearing a hat — `IBS\Client` overrode `getSession()`/`setSession()`/`setRoleCredentials()`/`useHighPerformanceConnectionSetup()` only to throw `UnsupportedFeatureException`, and no-opped `autoIDNConvert()` (a refused-bequest smell). RSRMID-2911 resolved it per-method rather than moving all four:
  - `useHighPerformanceConnectionSetup()` is **brand-agnostic** (a pure scheme+host rewrite to loopback via `getURL()`/`setURL()`) — it **stays on `AbstractClient`** and is now available (opt-in) on IBS/Moniker too; the caller supplies the local proxy.
  - `getSession()`/`setSession()` were kept **on `AbstractClient`** on the grounds that every brand's `SocketConfig` already implemented them (`AbstractSocketConfig` returned `""`/no-ops), making them "harmless" on IBS/Moniker. **This sub-decision was reversed in RSRMID-2920 — see the session-seam bullet below.** They now live on `CNR\Client`. (IBS's throwing overrides were deleted here and have not come back.)
  - `setRoleCredentials()` is **genuinely CNR-only**: it depends on the role separator, which is `""` on `AbstractSocketConfig`/IBS and only `":"` on CNR, so inheriting it on IBS would silently forge a garbage `<uid><role>` login. It moved onto **`RoleCredentialsInterface`** (in `CNIC\`, `@psalm-api`, single method), implemented only by `CNR\Client`, and was removed from the shared type. Consumers holding the shared `AbstractClient` narrow via `instanceof \CNIC\RoleCredentialsInterface` before calling it — exactly the `ExtendedResponseInterface` pattern. Do **not** re-add `setRoleCredentials()` to `AbstractClient`.
  - `autoIDNConvert()`'s IBS override was **redundant dead code**: `IBS\SocketConfig::$needsIDNConvert = false` already makes the base method short-circuit and return the command verbatim. The override was deleted; a comment on the flag carries the intent. (Ref: RSRMID-2911.)
- **The session seam is CNR-only, and absence is the chosen policy (RSRMID-2920, breaking, v22.0.0).** The config tree kept the half of the RSRMID-2911 split that the client tree had already cut. `AbstractSocketConfig` carried five CNR concepts as **null objects** — `getSession()` returned `""`, `setSession()`/`setPersistent()` returned `$this` unchanged, `getPersistent()` returned `false` — while `CNR\SocketConfig` re-declared `private $session`/`private $persistent` and overrode all of them. Session state therefore existed in two places, and because the setters are fluent, `ClientFactory::ibs()->setSession("SESSION-ABC")` looked accepted and was discarded (`getSession()` then reported `null`). On top of that the CNR-only `persistent=1` wire parameter was appended by the shared `getPOSTData()` for every brand, and `getRoleSeparator()` sat on the shared config with exactly one consumer — `CNR\Client::setRoleCredentials()`, itself already CNR-only. What changed:
  - The five accessors, `$session`, `$persistent` and `$roleSeparator` now exist **only** on `CNR\SocketConfig`; `persistent=1` is emitted by CNR's own `getPOSTDataParams()` (appended last, so the encoded body is byte-identical). `AbstractSocketConfig::getPOSTData()` is now purely the `http_build_query()` step and knows nothing brand-specific.
  - `getSession()`/`setSession()` moved from `AbstractClient` to `CNR\Client`, and the empty `IBS\SessionClient`/`MONIKER\SessionClient` were deleted. `MONIKER\Client` stayed **non-final** on purpose: Psalm's `ClassMustBeFinal` fired on it once nothing extended it, but that rule only ever fires on leaf classes, so `CNR\Client`/`IBS\Client` escape it purely because something inside the repo extends them — sealing one brand on that accident would make consumer extensibility differ per brand for an inexplicable reason. The issue is suppressed at the class with that rationale. A welcome side effect: deleting the `final` leaves removed the source of the `LessSpecificReturnStatement` false positive on the inherited fluent setters, so that `src/` suppression came out of `psalm.xml` (`findUnusedBaselineEntry` proved it dead).
  - `CNR\Client::cnrConfig()` is the **single narrowing point** from the shared `AbstractSocketConfig` property type to `CNR\SocketConfig`. It exists because PHP typed properties are invariant — a subclass cannot re-declare `$socketConfig` with a narrower type, so the covariant `newSocketConfig()` factory cannot inform the property's type. It uses an `instanceof`-guard-with-throw (`UnsupportedFeatureException`), never `assert()`, per the factory bullet below; the guard is unreachable in practice.
  - **The policy question this settled.** The project held two opposite answers for the same defect class — a capability the platform cannot honour. RSRMID-2911 chose *silence* (these no-ops, recorded as "harmless"); RSRMID-2919 chose *noise* for transport-owned cURL options (`UnsupportedFeatureException` "rather than being ignored"). An integrator learned which applied by testing. RSRMID-2920 picked a third answer available only here: **absence**. Nothing to call means a static-analysis error at the call site, which beats both a runtime throw and a silent discard. Prefer absence where the type system can express it; where a method must exist on the shared surface, throw (RSRMID-2919). Never no-op.
  - Guarded by `tests/ClientSessionSeamTest.php`. Absence cannot be tested behaviourally — calling a method that is gone is a fatal `Error` — so reflection is the only instrument that can catch the stubs creeping back up. That is exactly why they survived from v11 to v21.
- **Config-driven:** Each sub-namespace's `SocketConfig` (extending `AbstractSocketConfig`) carries the API config as typed properties — endpoints (`$liveUrl`/`$oteUrl`), the POST parameter map (`$parameters`), and feature flags (`$socketTimeout`, `$needsIDNConvert`). Brand-specific state stays on the brand config: `$session`, `$persistent` and `$roleSeparator` are `CNR\SocketConfig`-only (see the session-seam bullet above). (Historical note: this config previously lived in per-namespace `config.json` files, removed in favour of typed properties.)
- **Interfaces:** `ColumnInterface`, `RecordInterface`, `ResponseInterface`, `ExtendedResponseInterface`, `LoggerInterface` (all in `CNIC\`) define contracts. All concrete classes formally declare `implements`:
  - `CNR\Column`, `IBS\Column` → `ColumnInterface`
  - `CNR\Record`, `IBS\Record` → `RecordInterface` (both extend `AbstractRecord`, which implements it)
  - `CNR\Response` → `ExtendedResponseInterface` (which extends `ResponseInterface`); `IBS\Response` → `ResponseInterface` (both extend `AbstractResponse`, which implements the core `ResponseInterface`)
  - `CNR\Client` → `RoleCredentialsInterface` (the CNR-only role-login seam; IBS/Moniker deliberately do not implement it)
  - `CNR\Logger`, `IBS\Logger` → `LoggerInterface`
  - Type-hint against the interface rather than the concrete class (e.g. `LoggerInterface` not `Logger`, `ResponseInterface` not `Response`). Narrow to `ExtendedResponseInterface` only when you need one of the 5 CNR-only Response capabilities, and to `RoleCredentialsInterface` only for CNR role credentials.
- **Static utilities:** `ResponseParser::parse()` and `ResponseTranslator` (both `CNR\` and `IBS\`) for parsing/translating raw API responses; `CommandFormatter::flattenCommand()` for request serialisation. The brand `ResponseTemplateManager` and `ResponseTranslator` classes extend the shared `CNIC\AbstractResponseTemplateManager` / `CNIC\AbstractResponseTranslator` bases above and keep only their per-brand data + hooks — when changing template/translation behaviour, edit the shared pipeline in the abstract and the brand differences in the hooks, don't reimplement the pipeline per brand.
- **Factory pattern:** `ClientFactory` exposes **typed named constructors** — `cnr(): CNR\SessionClient`, `ibs(): IBS\Client`, `moniker(): MONIKER\Client` — not a string-dispatch `getClient(string): AbstractClient`. Each returns the concrete brand client fully typed, so every capability that brand supports (shared **and** brand-specific — CNR `getSession()`/`setSession()`/`login()`/`logout()`/`saveSession()`/`setRoleCredentials()`) is available directly, with **no** `assert`/`instanceof` narrowing on the normal path. Only CNR has a `SessionClient`; the IBS/Moniker ones were empty and were deleted in RSRMID-2920. Narrowing survives only when code deliberately holds the shared `AbstractClient` base and reaches a brand-specific method; where that occurs, use an `instanceof`-guard-with-throw, never `assert()` (PHP compiles `assert()` out when `zend.assertions` is disabled). The old `Registrar` enum and `UnknownRegistrarException` were **removed** with `getClient()` — an unknown registrar is now impossible by construction. The per-request endpoint path `request(array $cmd = [], string $path = "")` is symmetric across all brands and part of the shared contract (see next bullet). (Ref: RSRMID-2911, superseding the v17.1.0/commit 5cea723 shared-`AbstractClient` return type; the string factory predated it.)
- **Request lifecycle is a template method; `request()` is symmetric across brands:** the shared ~7-step pipeline (build command → resolve connection URL → serialise POST → cURL → construct Response → optional debug log) lives once on `AbstractClient::performRequest(array $cmd, string $path = "")`. Brands vary it through exactly **two hooks plus one property**: `buildCommand()` (CNR flattens as-is; IBS injects `ResponseFormat=JSON`), `newResponse()` (covariant Response factory), and the `$curlopts` property — which **no brand currently varies**: IBS/Moniker used to seed `CURLOPT_IPRESOLVE => CURL_IPRESOLVE_V4` through the `getDefaultCurlOpts()` hook, removed in RSRMID-2915 (see below), so every brand now starts from an empty bag. The public `request(array $cmd = [], string $path = "")` is a thin per-brand wrapper that pins the default `$path` and declares its concrete Response return via a one-line `assert($r instanceof Response)` (keeps CNR consumers' direct access to `ExtendedResponseInterface` and satisfies PHPStan L9). Every brand's SocketConfig now configures the **host only** (trailing slash, no path): CNR appends its default `api/call.cgi`, while IBS/Moniker pass a per-operation `$path` (e.g. `Domain/Create`). This symmetry is deliberate — RSRMID-2909 **dropped** the earlier "CNR must never accept a per-request path" rule in favour of full brand symmetry. When adding a brand or changing parsing, implement the hooks; never reimplement `performRequest()`. (Ref: RSRMID-2909, superseding RSRMID-2864.)
- **Date/time values are parsed on demand, never rewritten into the response:** `CNIC\ApiDateTime` is a standalone, immutable, UTC-only value object — deliberately **not** a `\DateTimeInterface` — that turns the two shapes the APIs emit (`Y-m-d H:i:s` with an optional fractional part from CNR; bare `Y-m-d` from IBS/Moniker) into one flat struct: `?int $ts`, `string $date`, `?string $dateTime`, `string $tz` (the last structurally pinned to `"UTC"` by a private constructor). It sits outside the Response/Record tree entirely and nothing in `src/` calls it — `getPlain()`/`getHash()`/`getListHash()` keep returning raw API strings and the consumer opts in at the point of display. Four decisions carry the design:
  - **Opt-in parser, not a response transformation.** The original ticket proposed rewriting date columns in the hash responses into a nested `{original, localized}` structure. Rejected: it is a breaking change on every consumer and bakes a server-side timezone assumption into data. Additive parser instead — a minor bump, no `BREAKING CHANGE`, no MIGRATION.md entry.
  - **Parser, not formatter.** No `in($tz)`, no locale formatting, no `ext-intl` (which the WHMCS `castDate()` helper needed and which the SDK will not take on), and no view-layer markup helpers — `toHtml()`/`assetPath()` were dropped from the planned surface when localization was split out to RSRMID-2916. Consumers localize from `json_encode($dt->toArray())` or `new \DateTimeImmutable("@{$dt->ts}")`. The field names are a superset of WHMCS `castDate()`, so that integration can drop its private copy.
  - **Strict two-stage parse, because neither stage alone suffices** (verified on PHP 8.3.31). An anchored regex gate runs first, because `createFromFormat("!Y-m-d", "2026-7-1")` succeeds with *zero* warnings; then `createFromFormat()` in an explicit UTC `\DateTimeZone` (so the process default timezone cannot shift the instant), rejecting on **any** `getLastErrors()` warning — because PHP reports out-of-range components as a *warning* while still handing back a rolled-over object (`2026-13-45` → `2027-02-14`, `2026-02-30` → `2026-03-02`, `0000-00-00` → `-0001-11-30`, `25:00:00` → next day `01:00`). A `$parsed === false` check alone would let all of those through. Fractional seconds are matched and discarded; offset-bearing values (`Z`, `+02:00`) and the ISO `T` separator are rejected rather than assumed to mean UTC — the accept-set is exactly what the APIs emit.
  - **`ts` and `dateTime` are null together for date-only values**, and `date` is always populated. `dateTime` deliberately does **not** fall back to `date`: `strtotime($dt->dateTime)` on a fallback would return midnight UTC — precisely the fictitious instant `ts === null` exists to refuse. Null makes it fail loudly (`strtotime(null)` is a TypeError on PHP 8.1+). `tz` stays `"UTC"` even for date-only values: it describes the source *declaration*, not an instant. `castDate()`'s companion `tzAbbr` field is **not** carried over — there it held the abbreviation *at that instant* (`CET`/`CEST`), a distinction that cannot exist in a UTC-only type whose zone id and abbreviation are the same string and which has no DST, so it would duplicate `tz` in every value forever. One brand-neutral parser suffices because `src/IBS/ResponseParser.php` already normalises `/` to `-` on IBS/Moniker date keys, aligning them with CNR. (Ref: RSRMID-2318; localization split to RSRMID-2916.)
- **Public API annotation:** classes and interfaces that form the public API are annotated `@psalm-api` to suppress unused-symbol warnings
