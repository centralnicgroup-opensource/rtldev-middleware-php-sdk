# Architecture (deep dive)

Full architectural reference for the PHP SDK.

> **What this file is for.** It records what neither the code nor `git log` can: the alternative that was rejected and why, the failure mode each decision prevents, empirical results that are expensive to re-derive, and the condition under which a decision should be revisited. It is **not** a changelog — what a refactor changed belongs in [MIGRATION.md](../../MIGRATION.md) and the commit; it is **not** a class inventory — that is derivable from `src/` in a couple of greps, and a prose copy drifts while the code cannot. This file has twice had to correct its own claims about the code, both times in descriptive prose rather than in a decision.
>
> **Every record keeps to four fields, and anything that fits none of them is history and does not belong here:** a **directive** (imperative, one line), the **failure mode** it prevents, the **alternative rejected** plus any empirical result, and the **revisit condition** with the **guard test** filename. A record must not restate its guard's class docblock — CONTRIBUTING.md already requires that docblock to carry the directive, the failure mode and the revisit condition, so the record names the file and stops.
>
> CLAUDE.md carries a trip-wire pointing here, not a summary. A green suite is not evidence a decision still holds — most of these refactors are behaviour-preserving the day they land, which is why the guards are structural.
>
> `src/` docblocks and MIGRATION.md reference entries below **by name** ("the parse-seam entry", "the `ApiDateTime` entry"). Keep those identities when editing.

## Shape of the tree

`CNIC\` maps to `src/` (PSR-4), with `CNR`/`IBS`/`MONIKER` sub-namespaces. Read the inheritance chain and member lists off `src/`. The facts about the tree that are **decisions** rather than structure:

- **The brands are siblings, not parent/child.** `CNR\Response` and `IBS\Response` both extend `AbstractResponse`; neither is-a the other. IBS previously extended `CNR\Response` and threw `UnsupportedFeatureException` from 5 inherited CNR-only methods — a refused bequest. `MONIKER\Client extends IBS\Client` because they are the same API platform (only the `SocketConfig` differs), and is deliberately **not** `final` — see the session-seam entry. MONIKER has no `Response` of its own. (RSRMID-2904, RSRMID-2923.)
- **Response construction is a template method.** `AbstractResponse::__construct()` is the skeleton; brands supply `translate()`, `populate()`, `newRecord()` and `newResponseParser()`, each `#[\Override]`. **Never reimplement the constructor** — its shape is load-bearing, and the parse-seam entry below deliberately added a *sixth* dispatch rather than opening it up.
- **Placeholder stripping is per-field, not global.** `AbstractResponseTranslator` strips `{UPPER}` placeholders through a per-field callback confined to the human-readable field (`description` for CNR, `message` for IBS). **Failure mode:** a global strip corrupts `{UPPER}` content in real data fields. (RSRMID-2893.)

## Decision records

- **The pagination seam is deliberately asymmetric — do not "simplify" it by hoisting single-page defaults (RSRMID-2912 declined, RSRMID-2918).** `AbstractResponse` implements the 5 getters that are pure functions of the primitives (`getNextPageNumber`/`getNumberOfPages`/`getPagination`/`getPreviousPageNumber`/`getRecordsCount`); the 7 primitives (`getCurrentPageNumber`/`getFirstRecordIndex`/`getLastRecordIndex`/`getRecordsTotalCount`/`getRecordsLimitation`/`hasNextPage`/`hasPreviousPage`) stay per brand. The ticket was **declined and closed as Cancelled**, so this entry is the authoritative record, not the ticket.
  - **Failure mode: a silent wrong answer.** Today a brand that forgets pagination cannot be instantiated — PHP raises a declaration-time fatal for the unimplemented interface methods. With base defaults it would quietly report "page 1 of 1, no next page", and a consumer paging a list would lose pages 2..N with no error anywhere. Never trade a loud compile-time error for a silent data-loss default.
  - **Rejected:** base defaults (above); and a `SinglePageResponse` trait, despite the `CNR\SessionCapable` precedent — with only two Response implementations, a default *or* trait would serve exactly one consumer.
  - Note the 7 are plain `ResponseInterface` methods the base never implements, **not** members `AbstractResponse` declares `abstract`. Reflection lists them as abstract members of `AbstractResponse` while `getDeclaringClass()` points at `ResponseInterface` — the misreading that produced the declined proposal. The status/code accessors are in the same category; what is specific to pagination is only the no-defaults rule. (`addColumn` used to be too, until RSRMID-2939 took it off the interface and made it a plain `protected` brand hook.)
  - **Revisit** only if a third genuinely non-paginating brand arrives. **Guard:** `tests/ResponsePaginationSeamTest.php`.
- **A `Response` is sealed once constructed, and its records are iterated rather than stepped (RSRMID-2939, breaking, v31.0.0).** `ResponseInterface` lost six methods: the mutators `addColumn()`/`addRecord()` (now `protected`) and the record cursor `getCurrentRecord()`/`getNextRecord()`/`getPreviousRecord()`/`rewindRecordList()` (gone, with the three `protected` `has*Record()` predicates and the `$recordIndex` property). The interface `extends \IteratorAggregate<int, RecordInterface>`; consumers `foreach`, or use `getRecord(int)`/`getRecords()`.
  - **Five undeclared rules, all now type-enforced or impossible.** (1) Constructor step order was load-bearing and enforced only by a comment — `populate()` read `$this->command`/`$this->parser`/`$this->raw`, and moving the `$this->command` assignment below the call silently switched the IBS parser's wire branch. It now takes `populate(string $raw, ResponseParserInterface $parser, array $cmd): void`, so there is no order to get wrong and no `$parser` property at all. (2) A column added post-construction was absent from every record (records are assembled from the columns once, at the end of `populate()`). (3) `assembleRecords()` appended, so it was not idempotent; it now replaces. (4) A duplicate column name half-registered via `??=`, leaving `getColumns()` holding a column `getColumn()` could never return; `registerColumn()` now throws `DuplicateColumnException`. (5) The only way to query the cursor was to move it — the predicates were `protected` while `getNextRecord()` advanced shared state, so two consumers holding one response interfered.
  - **`getCurrentRecord()` went too, though the ticket only listed five methods.** With nothing able to move `$recordIndex`, it would have been a permanently frozen alias for `getRecord(0)` — a name that lies about what it does. Removing it makes the interface shrink by six, not five.
  - **The `DuplicateColumnException` throw is deliberately unreachable today** — not dead code by oversight. Both brands derive column names from `array_keys()` of the parsed hash, and two distinct PHP array keys cannot stringify to one name, so *not even a substitute parser* can reach it. It guards the three-list invariant against a future brand whose `populate()` builds columns some other way. Same policy as `CNR\Response::stringCells()`.
  - **Rejected:** keeping the cursor alongside `IteratorAggregate` (leaves the shared-state defect in place and gives two iteration idioms); making the response `Countable` (`getRecordsCount()` already exists, and `count($r)` would be ambiguous against `getRecordsTotalCount()`).
  - **Note for consumers, worth not re-deriving:** the old `getNextRecord()` pre-incremented, so a `while ($rec = $r->getNextRecord())` loop never saw record 0. A `foreach` ported from one legitimately sees **one more row**. Flagged in MIGRATION.md.
  - **Revisit** only on a concrete need to build a response incrementally from outside the brand's `populate()` — which does not exist today: responses are born from `AbstractClient::newResponse()`/`AbstractResponseTemplateManager::createResponse()`, each handing a whole raw payload to a constructor, and a substitute `ResponseParserInterface` already controls what a response contains without any mutator. **Guard:** `tests/ResponseSealSeamTest.php`.
- **Records use an output factory hook, columns hand a finished instance to a shared registrar — do not "symmetrise" them (RSRMID-2899, RSRMID-2923).** `AbstractResponse::addRecord()` delegates to abstract `newRecord(array $row): RecordInterface`. Columns cannot use that shape, so each brand's `addColumn()` builds its own correctly-typed Column and passes it to `AbstractResponse::registerColumn(ColumnInterface $col): static`, which owns the `$columns`/`$columnKeys`/`$columnIndex` bookkeeping once. Keep the `registerColumn()` shape. Both `addRecord()` and `addColumn()` are `protected` since RSRMID-2939 — the seam shape is unchanged, only its visibility.
  - **Rejected, and infeasible rather than merely unattractive:** a param-typed `newColumn(string, array): ColumnInterface`. A CNR column takes `string[]` and an IBS column mixed JSON values, so the base factory would have to narrow `array<array-key,mixed>` into CNR's `string`-bound constructor — rejected by both PHPStan L9 (`argument.type`) and Psalm L1 (`MixedArgumentTypeCoercion`), and the toolchain forbids silencing either. Sharing a column *base* is a different question from a param-typed *factory*; the value types still diverge, which is why the shared column is templated instead.
  - **No guard test** — this one is enforced by the analysers, and is listed in CLAUDE.md for that reason.
- **The record/column layer is one class each — do not re-split it per brand (RSRMID-2923, breaking, v25.0.0).** One concrete `CNIC\Record` and one concrete, templated `CNIC\Column`. `CNR\Column` is the only surviving brand column and earns its place solely by binding `TValue` to `string` and narrowing `getDataByIndex(): ?string`.
  - **`newRecord()` stays an abstract per-brand hook** even though both brands return the same class: it is the seam a brand with genuinely different row behaviour would implement, and hard-coding `new Record()` on the base would close it. A hook body *is* the brand's declaration of its record type — unlike the empty `class Record extends AbstractRecord {}` markers this deleted, which carried no decision.
  - **Empirical, and worth not re-deriving:** a covariant `?string` override against the base's `mixed` return is accepted by **both** PHPStan L9 and Psalm L1 with no suppression, and `@extends CNIC\Column<string>` is genuinely enforced — `new CNR\Column("X", [1, 2, 3])` is rejected by both. Net **loss** of one suppression: the hand-rolled `CNR\Column` needed `@psalm-suppress MoreSpecificImplementedParamType`, the template does not.
  - **Guard:** `tests/RecordColumnSeamTest.php`.
- **The parse step is a seam, not a static call (RSRMID-2924, breaking, v26.0.0).** `CNIC\ResponseParserInterface` declares one signature, `parse(string $raw, array $cmd = []): array`, and both brand parsers are instantiable classes implementing it. Previously `populate()` called `RP::parse()` statically with **different signatures** per brand, so no shared contract was even expressible and nothing in the Response tree could be exercised without a full raw wire payload.
  - **The shape is the `TransportInterface` one, deliberately:** an abstract `newResponseParser()` hook supplies the brand default, and an optional trailing `?ResponseParserInterface $parser = null` constructor argument overrides it. Adding an optional parameter is legal widening, so no implementation stops satisfying anything.
  - **CNR takes `$cmd` and ignores it, on purpose.** A contract covering only IBS's shape, or two contracts, buys nothing — CNR's wire format is self-describing, and a uniform signature is what lets one seam serve both brands.
  - **`AbstractResponseTemplateManager::parseResponse()` is gone**, replaced by the same `newResponseParser()`. It still parses with **no** command (a template is not tied to one) while `populate()` passes the command it was built with; for IBS that selects the JSON versus plain-text branch. **Trap when asserting on that divergence:** the command must be one *without* `ResponseFormat` — one carrying `ResponseFormat=JSON` takes the same branch as the empty one and makes the assertion vacuous.
  - **A non-string cell — and equally a column entry that is not a list — throws** `UnsupportedFeatureException` naming the column, from `CNR\Response::stringCells()`. Skipping would be the silent no-op RSRMID-2919/RSRMID-2920 ruled out; coercing would invent a value the wire could never carry. The container half is the one that is easy to forget: `foreach ((array)$values …)` turns a bare string into a one-cell column while a bare `int` still throws a line later. Deliberately asymmetric with the level above: a **missing or non-array `PROPERTY` block** yields no columns rather than throwing, because most CNR responses legitimately have none.
  - **`resetTemplates()` is `addTemplate()`'s counterpart, not a general undo, and a direct assignment to the public `$templates` property escapes it** — the RSRMID-2921 lesson that a guard on one writer does not protect state with several. Closing that writer means making the property non-public, which `CNR\ResponseTranslator::templates()` reads across a class boundary; that is a separate change.
  - **Build-then-populate remains impossible by design.** The seam **adds a sixth** constructor dispatch rather than removing any, because injection makes the parse step substitutable without touching the constructor's load-bearing shape. **Revisit** as a ticket about the constructor, not about parsing.
  - **Guard:** `tests/ResponseParserSeamTest.php` (behavioural half via `CNICTEST\Support\SpyResponseParser`, structural half against a re-inlined `new RP()`).
- **The logger seam is at the format, not the sink (RSRMID-2925, breaking, v27.0.0).** `LoggerInterface::format(string $post, ResponseInterface $response, ?string $error = null): string` owns what varies per brand; `CNIC\LogSinkInterface::write(string): void` owns the destination. `CNIC\AbstractLogger` holds the sink (default `CNIC\EchoSink`), implements `log()` as `sink->write(format(…))` and leaves `format()` abstract. Previously the seam sat where nothing varied — every brand ended in `echo` — while the part that does vary returned nothing and could only be observed by capturing output.
  - **`AbstractLogger::log()` is `final`, and that is the load-bearing part.** A subclass reintroducing `log()` is behaviour-identical under the default echo sink and silently ignores an injected one. `final` turns that from an invisible regression into a declaration-time fatal.
  - **`setDefaultLogger()` was replaced by the protected `newLogger(LogSinkInterface $sink)` hook** plus public `AbstractClient::setLogSink()`. Without the hook, choosing a destination would mean `setCustomLogger(new CNIC\CNR\Logger($sink))` — naming a brand concrete at the call site, which is exactly what this project tells integrators not to do. `setLogSink()` rebuilds the brand logger and therefore **discards a previously set custom logger**; the two seams deliberately do not compose (a `LoggerInterface` has no sink slot), so last call wins and the order is pinned in both directions.
  - **Rejected:** a second logger interface instead of a sink. Two real implementations justify the sink immediately (`EchoSink`, `CNICTEST\Support\CollectingSink`), and it gives the WHMCS/Blesta bundles the brand's format for free. Note what the sink deliberately does **not** get: the response. A PSR-3 adapter deriving severity from the response status writes a `LoggerInterface`, not a sink — handing the response to both halves would make the split meaningless.
  - **Masking is unaffected** — both inputs are masked upstream (`sanitizeCommand()`, and `performRequest()` passing `getPOSTData($mycmd, true)`). **Trap:** assert on a `$post` built through the real client, never a hand-written pre-masked literal — the IBS format never renders `getCommand()`, so the POST body is its only secret-bearing input, and a literal passes with masking switched off entirely.
  - **Guard:** `tests/LoggerSeamTest.php`.
- **Core vs. extended Response contract — do not re-add the 5 extended methods to the core interface (RSRMID-2904).** `ResponseInterface` is the **universal** contract every brand fully supports. The richer CNR-class capabilities — telemetry (`getQueuetime()`/`getRuntime()`), transient/pending status (`isTmpError()`/`isPending()`) and `getListHash()` — live on `ExtendedResponseInterface extends ResponseInterface`, implemented **only** by `CNR\Response`. On IBS/Moniker those 5 are **absent**, not present-and-throwing. `AbstractClient::request()` returns the core interface, so a consumer holding the shared type narrows via `instanceof \CNIC\ExtendedResponseInterface`; consumers holding `CNR\Client`/`CNR\Response` are unaffected because `CNR\Client::request()` returns the concrete type.
- **`IBS\Response::getStatus()` was removed rather than promoted to a capability interface (RSRMID-2927, breaking, v28.0.0).** It returned the raw `status` hash key with zero callers in `src/` — every internal consumer already reads that key through protected `getHashString()`, and external consumers can reach it through the universal interface via `getHash()["status"]`.
  - **The judgment worth reusing:** a single method that only duplicates an already-interface-reachable hash lookup does not justify a new one-method capability interface plus the `instanceof` ceremony — unlike the CNR-only 5-method cluster that did justify `ExtendedResponseInterface`. This was a plain unused-API removal, not a repeat of the absence-vs-throw-vs-no-op policy question.
  - **Deliberately not guarded specifically.** Nothing pins "this method must stay gone"; a re-added public method not on any interface is caught by the sweep below, which is stronger than a one-off regression test naming `getStatus()`. Consumer path: [MIGRATION.md → v28.0.0](../../MIGRATION.md#-v2800), including the one case (`Domain/Check`'s `AVAILABLE`/`UNAVAILABLE`) where reading that key is the only way to get the answer — `isError()`/`isSuccess()` report only whether the *command* succeeded.
- **A sweep guards that every public method is reachable through the interfaces CLAUDE.md mandates typing against (RSRMID-2927).** `tests/InterfaceCoverageSeamTest.php` derives each concrete class's FQCN from its PSR-4 path and, for those implementing a "total" interface (the 7 meant to fully describe their implementors — `ResponseInterface`, `RecordInterface`, `ColumnInterface`, `TransportInterface`, `ResponseParserInterface`, `LoggerInterface`, `LogSinkInterface`), checks every public method for two defect shapes: **stray** (on none of them — the `getStatus()` shape) and **widening** (more parameters than the interface declares — the `getColumnKeys(bool)` defect fixed in `4b3ff7b`).
  - **`ExtendedResponseInterface`/`RoleCredentialsInterface` are excluded from the "total" role** because they are additive capability interfaces, not descriptions of everything their implementor exposes; treating either as total would flag `CNR\Client`/`CNR\SessionClient`'s ~20 legitimate methods as stray. They still count as declaring interfaces, so `CNR\Response`'s 5 extended methods resolve rather than being reported themselves.
  - **The allow-list is empty and stays that way.** A future stray or widened method is a defect to fix at the source, not a reason to grow an exception list.
  - **`tests/ResponseInterfaceConsumerTest.php` was deliberately kept, not folded in.** The sweep is a *mechanism* check; the consumer test additionally pins *behaviour* through the interface (`getColumnKeys(true)` genuinely strips pagination keys) and the no-constructor rule. Replacing one with the other drops a behavioural pin.
- **An interface declaration must match its implementation, and must not describe construction (RSRMID-2918, RSRMID-2923).** Two drifts on `ResponseInterface` resolved in *opposite* directions, which is the instructive part.
  - **`getColumnKeys()` — widen the interface to match the implementation.** The interface declared no parameter while `AbstractResponse` had always implemented `getColumnKeys(bool $filterPaginationKeys = false)`. Because this project mandates typing against the interface, the capability was **unreachable to exactly the consumers told to depend on it** — the call ran, but the analysers rejected it, leaving only bad workarounds. **General rule: when a parameter is added to an implemented method, add it to the interface in the same change.** That is breaking for direct implementers.
  - **`__construct()` — delete it from the interface instead.** Nothing constructs through these types: responses come from `AbstractClient::newResponse()`/`AbstractResponseTemplateManager::createResponse()`, columns from a brand's `addColumn()`, records from `newRecord()` — all naming concrete classes. Construction is the factories' concern; the interface describes what a value can be *asked*. Removal only relaxes the contract, so it is non-breaking. `ColumnInterface`/`RecordInterface` followed in RSRMID-2923.
  - **Empirical correction, and it must not be re-reversed: a constructor declared on an *interface* is fully enforced.** PHP exempts constructors only in **class-to-class** inheritance; an incompatible implementation of an interface constructor is a declaration-time fatal. An earlier revision of this entry asserted the opposite from memory and made it the justification for a directive. The drift persisted for a mundane reason instead: `$context` is **optional**, and adding an optional parameter is legal widening. The decision is unaffected — but "an interface constructor is unenforced" is false. One 10-line script settled it; a language rule asserted from memory is worth 10 lines.
  - Related, and now historical: `CNR\Response::addColumn()` carried a `@psalm-suppress MoreSpecificImplementedParamType` for narrowing `array<array-key,mixed>` to `string[]` against the interface declaration. RSRMID-2939 removed that declaration, so nothing narrows and the suppression had to go with it — a never-applied suppression fails the lint (`UnusedIssueHandlerSuppression`). Net **loss** of one suppression. The general point stands: a suppression for an ordinary method's parameter variance is not the same defect class as an interface/implementation mismatch.
  - **To find this defect class again:** compare `getNumberOfParameters()` of every interface method against each implementation. **Guard:** `tests/ResponseInterfaceConsumerTest.php`.
- **Transport tuning is the caller's decision, not a brand default (RSRMID-2915, breaking in v20.0.0).** `IBS\Client`'s `getDefaultCurlOpts()` override forcing `CURLOPT_IPRESOLVE => CURL_IPRESOLVE_V4` is removed — it was a workaround for a handful of customers' IPv6-hostile hosts, hard-coded into everyone's transport. Affected integrations opt in with `setExtraCurlOptions()`, the API added in RSRMID-2913 deliberately *before* the default was withdrawn.
  - **The `getDefaultCurlOpts()` hook itself stays**, even with zero overrides: `resetCurlOptions()` is defined in terms of it (restoring defaults rather than blindly wiping the bag). **Revisit** only for a genuinely protocol-mandatory option — never to paper over one environment's networking.
  - **Consequence for callers:** an opted-in option is *caller* state, so `resetCurlOptions()` discards it, whereas IPv4 used to survive a reset as a brand default.
  - **Guard:** `ClientConfigSeamTest::testNoBrandOverridesTheDefaultCurlOptsHook()` and `testClientsHaveNoCurlOptionDefaultHook()` (the hook moved to `AbstractSocketConfig` with the bag in RSRMID-2921).
- **The caller wins on cURL options, except on a closed set the transport owns — and rejection is loud (RSRMID-2919, breaking in v21.0.0).** `HttpTransport::post()` did `curl_setopt_array($h, [defaults] + $options)`, and PHP's `+` keeps the **left** operand, so 11 keys never reached the wire: a caller asking for a 5s timeout silently got 300s while the client's bag and the unit tests both looked right. The operands are swapped, and transport-owned keys are rejected rather than ignored.
  - **Rejected: simply swapping the operands.** The 11 colliding keys were three different things and only one was a defect. *Envelope invariants* (`URL`, `POST`, `POSTFIELDS`, `RETURNTRANSFER`, `HEADER`) must stay unoverridable or parsing breaks — `RETURNTRANSFER => 0` makes `curl_exec()` return `true` and the parser gets nothing. *Security posture* (`SSL_VERIFYPEER`/`SSL_VERIFYHOST`) was protected only by accident, but a generic convenience bag is the wrong place to disable certificate verification. *Legitimate tuning* (`TIMEOUT`, `CONNECTTIMEOUT`, `HTTPHEADER`, `USERAGENT`) is where the bug was, and is now caller-overridable.
  - **`HttpTransport::PROTECTED_OPTIONS` is public** so consumers and tests can read it, and passing any of them raises `UnsupportedFeatureException` naming the constants **before the handle is touched** — a rejected option is a programming error, not a network event, and must not cost a request. Silence was the whole defect; do **not** downgrade this to an ignore.
  - **`CURLOPT_HTTPHEADER` is additive, and the transport's own four lines (`Expect:`, `Content-Type`, `Content-Length`, `Connection`) are protected too**, matched case-insensitively. `Content-Type`/`Content-Length` derive from the POST body and `Connection` from the reused handle, so overriding one corrupts the request exactly as overriding `CURLOPT_POSTFIELDS` would — and a wrong `Content-Length` fails *silently*. Replacing wholesale would drop the transport's entries; appending blindly would put two `Content-Type` lines on the wire and leave the winner to the server; so a collision is an error, not a merge. A non-array `CURLOPT_HTTPHEADER` is deliberately left for cURL's own `TypeError` (verified: `curl_setopt_array()` raises before `curl_exec()`, so nothing is sent).
  - **A negative socket timeout is rejected at the setter** via `InvalidConfigurationException`. Not gold-plating: verified on PHP 8.3.31 that `curl_setopt($h, CURLOPT_TIMEOUT, -5)` returns `false`, and `HttpTransport` does not inspect `curl_setopt_array()`'s return — so a negative value would be dropped with no signal, the same silent divergence reintroduced by the very setter added to end it. Use this type for *configuration values out of range*, as distinct from `UnsupportedFeatureException` (capability absent).
  - **The lesson the old test taught: "in the bag" is not "on the wire".** `testSetExtraCurlOptionsMergesOverTheBag()` asserted the bag and passed for two releases while half the options it described were discarded. Assertions about transport behaviour must observe the *effective* arguments. **Guards:** `tests/HttpTransportCurlOptionsTest.php` (rejection, offline; `testProtectedOptionsAreExactlyTheEnvelopeAndTlsKeys()` pins the list in both directions), `tests/Functional/HttpTransportTest.php` (the merge over a loopback socket, asserting the effect not the option value), `CNICTEST\Support\SpyTransport` (what the client hands the transport).
- **Client contract segregation, resolved per-method rather than wholesale (RSRMID-2911).** `AbstractClient` was a CNR base wearing a hat: `IBS\Client` overrode four methods only to throw and no-opped a fifth.
  - `useHighPerformanceConnectionSetup()` is **brand-agnostic** and stays on `AbstractClient`, opt-in on IBS/Moniker too — the caller supplies the local proxy.
  - `getSession()`/`setSession()` were kept on the base here on "harmless null object" grounds. **That sub-decision was reversed in RSRMID-2920** — see the session-seam entry.
  - `setRoleCredentials()` is **genuinely CNR-only**: it depends on the role separator, `""` everywhere but CNR, so inheriting it on IBS would silently forge a garbage `<uid><role>` login. It moved to `RoleCredentialsInterface` (implemented only by `CNR\Client`); shared-type consumers narrow via `instanceof`. Do **not** re-add it to `AbstractClient`.
  - `autoIDNConvert()`'s IBS override was dead code behind a flag. **This is the one method the per-method resolution got wrong** — it kept CNR rules on the shared base and settled for a flag disabling them, the same shape as the session null objects. Finished in RSRMID-2922; see the IDN entry.
- **The session seam is CNR-only, and absence is the chosen policy (RSRMID-2920, breaking, v22.0.0).** `AbstractSocketConfig` carried five CNR concepts as **null objects** while `CNR\SocketConfig` re-declared and overrode all of them, so session state existed in two places — and because the setters are fluent, `ClientFactory::ibs()->setSession("SESSION-ABC")` looked accepted and was discarded. The five accessors, `$session`, `$persistent` and `$roleSeparator` now exist **only** on `CNR\SocketConfig`; `persistent=1` is emitted by CNR's own `getPOSTDataParams()` (appended last, so the encoded body is byte-identical) and `AbstractSocketConfig::getPOSTData()` is purely the `http_build_query()` step. `getSession()`/`setSession()` moved to `CNR\Client`, and the empty `IBS\SessionClient`/`MONIKER\SessionClient` were deleted.
  - **The policy this settled, and the most citable rule in this file.** The project held two opposite answers for one defect class — a capability the platform cannot honour. RSRMID-2911 chose *silence* (null objects, recorded as "harmless"); RSRMID-2919 chose *noise* (`UnsupportedFeatureException`). An integrator learned which applied by testing. The third answer, available only here, is **absence**: nothing to call means a static-analysis error at the call site, which beats both a runtime throw and a silent discard. **Prefer absence where the type system can express it; where a method must exist on the shared surface, throw. Never no-op.**
  - **`MONIKER\Client` stays non-final on purpose.** Psalm's `ClassMustBeFinal` fired once nothing extended it, but that rule only ever fires on leaf classes — `CNR\Client`/`IBS\Client` escape it purely because something inside the repo extends them, so sealing one brand on that accident would make consumer extensibility differ per brand for an inexplicable reason. Suppressed at the class with that rationale.
  - **`CNR\Client::getSocketConfig()` is the single narrowing point** from `AbstractSocketConfig` to `CNR\SocketConfig`, because PHP typed properties are invariant — a subclass cannot re-declare `$socketConfig` narrower, so the covariant `newSocketConfig()` factory cannot inform the property's type. It uses an `instanceof`-guard-with-throw, never `assert()`. There is deliberately **no alias**: two methods narrowing the same property would be two places to keep in step.
  - **Guard:** `tests/ClientSessionSeamTest.php`. Absence cannot be tested behaviourally — calling a method that is gone is a fatal `Error` — which is exactly why the stubs survived from v11 to v21.
- **Connection configuration has exactly one home, and two invariants keep it that way (RSRMID-2921, breaking, v23.0.0).** State was split between `AbstractClient` and `AbstractSocketConfig` with no invariant tying the copies together. The root cause was structural: **there was no accessor for `$socketConfig` on the client**, so every value needed a hand-written forwarder or was unreachable — which is why ~26 accumulated and why `AbstractClient` was the repo's highest-churn file (43 touches in 120 commits).
  - **The division of labour.** The config owns *the connection*: where to connect (`$url`, `$oteUrl`/`$liveUrl`, `$highPerformance`), how to authenticate, and how the transport behaves (`$socketTimeout`, `$proxy`, `$referer`, `$curlOptions`). The client owns *client behaviour*: logger and `$debugMode`, `$context`, the transport instance, and the SDK's identity (`VERSION`/`$userAgent` — kept on the client because semantic-release rewrites `VERSION` in that file).
  - **Invariant 1 — the system is derived, never stored.** `getSystem(): ?System` compares `$url` to the two endpoints. The nullable return is the point: after `setURL("https://staging.example/")` there is no honest OT&E-or-LIVE answer, and reporting the last selection is exactly how the `useOTESystem()->setURL($custom)` drift happened. Taken in the direction that keeps `setURL()` authoritative.
  - **Invariant 2 — a value the SDK models cannot also come from the cURL bag.** `AbstractSocketConfig::MANAGED_OPTIONS` (`CURLOPT_TIMEOUT`/`USERAGENT`/`PROXY`/`REFERER`) is rejected by `setExtraCurlOptions()` with an exception naming the owning setter — each already has one, and a bag value silently outranked it while the getter reported the setter's. Rejection is **eager** here (the config knows immediately) whereas `PROTECTED_OPTIONS` is checked on the next request (the transport is injectable, and which options it owns is its own business). Options the SDK has no opinion about — `CONNECTTIMEOUT`, `IPRESOLVE`, `HTTPHEADER` — stay caller-owned. **Guard:** `AbstractClientCurlOptionsTest::testManagedOptionsAreExactlyTheOnesWithTheirOwnSetter()`.
  - **High-performance routing is a flag applied inside `getURL()`, not a URL rewrite.** The eager rewrite was itself a drift: the loopback URL no longer matched the OT&E endpoint, so switching the mode on silently cost the caller `isOTE()`. Routing is *how* to reach the endpoint, not *which* one, so the selected system now survives it and it survives a later system switch.
  - **The ~26 forwarders were deliberately kept**, against the ticket's "collapse them" option: they are the documented consumer surface, and deleting them would rewrite every integration to fix nothing — a forwarder is one home with one answer, and the invariant is "no value readable from two places **with two possible answers**". What `getSocketConfig()` changes is that a *new* setting no longer needs one — so do not add one; `getSocketConfig()->getOTEUrl()` is the answer. **Rejected** in the opposite direction: absorbing the config into the client would cost the "configure without constructing a client" property that motivated the ticket.
  - **`getCurlOptions()` puts dedicated proxy/referer state on the *left* of the union, and that is load-bearing.** `setExtraCurlOptions()`'s guard is not the only writer of `$curlOptions` — `getDefaultCurlOpts()` seeds it and `resetCurlOptions()` re-seeds it, neither passing the guard. A brand default of `CURLOPT_PROXY` — exactly the protocol-mandatory case that hook is kept for — would bring the drift back **inverted**: the getter reporting the setter's value while the request used the default. `executeCurl()`'s third `$extraCurlOpts` parameter was removed for the same reason: an option route skipping `MANAGED_OPTIONS` is a way to put a second answer behind `getProxy()`. **Guard:** `AbstractClientConfigDriftTest::testDedicatedProxyStateBeatsABrandDefaultOnTheWire()`, which writes out the brand subclass that does not yet exist.
  - **Deliberately not addressed:** with debug mode on, `performRequest()` calls `getPOSTData()` twice to build the masked log line. It is not a second *home* — both calls read the same config and cannot disagree — and a masked variant genuinely needs a second pass; the alternatives (a `getPOSTDataPair()`-shaped API, or masking the encoded string) are not worth a debug-only saving.
  - **Guards:** `tests/ClientConfigSeamTest.php`, `tests/AbstractClientConfigDriftTest.php`.
- **CNR IDN command rewriting is a module, not a base-class method behind a flag (RSRMID-2922, breaking, v24.0.0).** `AbstractClient::autoIDNConvert()` was the largest method in that class and every line was CNR domain knowledge — which parameters carry a domain name (`PARENTDOMAIN|NAMESERVER|NS|DNSZONE` with an optional index; `DOMAIN` deliberately absent, the API converts that itself), and that `OBJECTID` is a *pattern* parameter whose content depends on `OBJECTCLASS` (RSRTPM-3167). It ran on a base shared with IBS/Moniker behind `needsIDNConvert`, a flag whose only job was to disable it for two brands out of three.
  - **The fix used a hook that already existed.** The rules live in `CNIC\CNR\IDNCommandRewriter::rewrite(array $cmd): array` — a `final` class of static rules, same shape as `CommandFormatter` — called from `CNR\Client::buildCommand()`. No brand detection replaced the flag, because the call site *is* the brand. **The generalisable form: when brand behaviour needs a flag on a shared class, the hook it should have used is usually already there.**
  - **Order matters and is pinned.** The rewrite runs *after* `flattenCommand()` (the rules match wire keys like `NAMESERVER0`, not the caller's nested input) and rewrites values in place, so the priority sort survives it.
  - **What stayed:** public `AbstractClient::IDNConvert()` — converting a caller-supplied list is brand-agnostic and has been public API since v7.1.0. **What went, breaking:** protected `autoIDNConvert()`, `needsIDNConvert` on all three configs, and `AbstractSocketConfig::getNeedsIDNConvert()`.
  - **The testability argument is why this was a ticket at all.** With no surface of its own, the behaviour was only reachable through `ReflectionMethod::setAccessible()`, which two test files did. **Where a test has to bypass the interface to reach the behaviour, the module is the wrong shape.** Note the distinction the repo now keeps by filename: reflection to *test behaviour* is the smell this removed; reflection to *guard absence* is unavoidable and lives in `*SeamTest.php`.
  - **Guards:** `tests/ClientIDNSeamTest.php` (absence of `autoIDNConvert()`/`needsIDNConvert`), `tests/AbstractClientIDNTest.php`, `tests/CNR/IDNCommandRewriterTest.php` (10 cases, including both halves of the `OBJECTID`/`OBJECTCLASS` decision and the absent-`OBJECTCLASS` case the reflection tests never covered).
- **Config-driven, and brand state stays on the brand config.** Each `SocketConfig` carries the API config as typed properties rather than the per-namespace `config.json` files this replaced.
- **Type-hint against the interface, not the concrete class** (`LoggerInterface` not `Logger`). Narrow to `ExtendedResponseInterface` only for the 5 CNR-only Response capabilities, and to `RoleCredentialsInterface` only for CNR role credentials.
- **Edit the shared pipeline in the abstract, the brand differences in the hooks** — the brand `ResponseTemplateManager`/`ResponseTranslator` classes hold only per-brand data plus hooks. Do not reimplement a pipeline per brand.
- **`ClientFactory` exposes typed named constructors** — `cnr(): CNR\SessionClient`, `ibs(): IBS\Client`, `moniker(): MONIKER\Client` — not a string-dispatch `getClient(string)`. Each returns the concrete brand client fully typed, so brand capabilities need **no** narrowing on the normal path. The old `Registrar` enum and `UnknownRegistrarException` went with `getClient()`: an unknown registrar is now impossible by construction. Where code *deliberately* holds the shared `AbstractClient` and reaches a brand method, use an `instanceof`-guard-with-throw, **never `assert()`** — PHP compiles `assert()` out when `zend.assertions` is disabled, so it cannot carry a runtime guarantee. (The `assert($r instanceof Response)` in each brand's `request()` is a different thing: a static-analysis hint about a return type the factory hook already guarantees.) (RSRMID-2911.)
- **The request lifecycle is a template method, and `request()` is symmetric across brands (RSRMID-2909, superseding RSRMID-2864).** The shared pipeline (build command → resolve URL → serialise POST → cURL → construct Response → optional debug log) lives once on `AbstractClient::performRequest()`; brands vary it through exactly **two hooks plus their config subtype** — `buildCommand()` (CNR flattens as-is, IBS injects `ResponseFormat=JSON`), `newResponse()`, and `newSocketConfig()`, where a brand-mandatory cURL option would now go. **No brand actually varies the transport bag** — every brand starts from an empty one. Every SocketConfig configures the **host only**: CNR appends its default `api/call.cgi`, IBS/Moniker pass a per-operation `$path`. The symmetry is deliberate: RSRMID-2909 **dropped** the earlier "CNR must never accept a per-request path" rule rather than preserving it. Never reimplement `performRequest()`.
- **Date/time values are parsed on demand, never rewritten into the response (RSRMID-2318; RSRMID-2926).** `CNIC\ApiDateTime` is a standalone, immutable, UTC-only value object — deliberately **not** a `\DateTimeInterface` — turning the two shapes the APIs emit (`Y-m-d H:i:s` with optional fraction from CNR; `Y/m/d` from IBS/Moniker) into one flat struct: `?int $ts`, `string $date`, `?string $dateTime`, `string $tz`, `string $raw`, with `tz` structurally pinned to `"UTC"` by a private constructor. It is never invoked during response construction; `src/` reaches it from exactly two opt-in accessors, and `getPlain()`/`getHash()`/`getListHash()` still return raw API strings.
  - **Opt-in parser, not a response transformation.** **Rejected:** the original proposal to rewrite date columns into a nested `{original, localized}` structure — breaking for every consumer, and it bakes a server-side timezone assumption into data.
  - **Parser, not formatter.** No `in($tz)`, no locale formatting, no `ext-intl` (which the WHMCS `castDate()` helper needed and the SDK will not take on), no view-layer markup — `toHtml()`/`assetPath()` were dropped when localization was split to RSRMID-2916. Consumers localize from `json_encode($dt->toArray())` or `new \DateTimeImmutable("@{$dt->ts}")`. The field names are a superset of `castDate()` so that integration can drop its private copy.
  - **Strict two-stage parse, because neither stage alone suffices** (verified on PHP 8.3.31). An anchored regex gate runs first, because `createFromFormat("!Y-m-d", "2026-7-1")` succeeds with *zero* warnings; then `createFromFormat()` in an explicit UTC `\DateTimeZone` (so the process default cannot shift the instant), rejecting on **any** `getLastErrors()` warning — PHP reports out-of-range components as a *warning* while still returning a rolled-over object (`2026-13-45` → `2027-02-14`, `2026-02-30` → `2026-03-02`, `0000-00-00` → `-0001-11-30`, `25:00:00` → next day). A `$parsed === false` check alone lets all of those through. Fractional seconds are matched and discarded; offset-bearing values (`Z`, `+02:00`) and the ISO `T` separator are rejected — the accept-set is exactly what the APIs emit.
  - **`ts` and `dateTime` are null together for date-only values; `date` is always populated.** `dateTime` deliberately does **not** fall back to `date`: `strtotime($dt->dateTime)` on a fallback returns midnight UTC, precisely the fictitious instant `ts === null` exists to refuse, whereas null fails loudly (`strtotime(null)` is a TypeError on PHP 8.1+). `tz` stays `"UTC"` even then: it describes the source *declaration*, not an instant. `castDate()`'s `tzAbbr` is **not** carried over — it held the abbreviation *at that instant* (`CET`/`CEST`), a distinction that cannot exist in a UTC-only type with no DST, so it would duplicate `tz` forever.
  - **Separator tolerance, both sides consistent (RSRMID-2926).** `PATTERN` accepts `-` or `/` via a captured `sep` group plus a `\k<sep>` backreference, so `2026-02/20` and `2026/02-20` are still rejected — as strict about shape as before, over a wider accept-set. `$date`/`$dateTime` always emit `-`, normalised before `createFromFormat()`, so the struct's shape never depends on which brand sent it. Still a parser: no new public method.
  - **`$raw` exists because the accessors closed the gap that used to guarantee the caller still had it.** Before `getDateTimeByKey()`/`getDateTimeByIndex()`, the only route was `ApiDateTime::tryFrom($hash["paiduntil"])`, so a caller necessarily still held the original string. It is populated from the constructor's `$value` at both `from()` call sites — **never** from the separator-normalised subject — and is the only place the fractional precision `$dateTime` discards survives. **Display/logging/round-trip only:** comparing or sorting on `$raw` reintroduces exactly the separator bug `$date`'s normalisation prevents (`"2026/02/20"` sorts wrong against `"2026-03-01"`). No getter, no `withRaw()`.
  - **`Record`/`Column` gained one opt-in accessor each, not a shared helper.** Each is a one-line narrowing (`is_string($v) ? ApiDateTime::tryFrom($v) : null`) declared on both the class and its interface. The line is duplicated deliberately: `Record` and `Column` have no composition relationship, so sharing it would either invent one or add an indirection with nothing behind it. Both interface declarations widen the public contract, which is what makes this breaking (v28.0.0) independent of the separator change. The accessor is **`CNIC\Column`-only** — `CNR\Column` gained nothing, guarded by `RecordColumnSeamTest::testCnrColumnNarrowsNothingButGetDataByIndex`.
  - **The IBS date-separator rewrite is deleted, and deliberately not guarded.** `IBS\ResponseParser` used to `array_walk_recursive()` and rewrite `/` to `-` in values whose key matched `/(date|paiduntil|expiration)$/i` — the only place in `src/` that mutated raw response data, and over-broad enough to turn `n/a` under an `updatedate` key into `n-a`. No guard is needed because re-adding it is **not** behaviour-preserving: it changes `getHash()`/`getPlain()`/`getListHash()` for every IBS/Moniker date field, so the ordinary parser/response/record/column assertions already catch it.
  - **The interface declarations are protected by `#[\Override]`, not by a test** — dropping them from `RecordInterface`/`ColumnInterface` while leaving the methods on the classes would otherwise be behaviour-preserving for the whole suite. `#[\Override]` makes it a declaration-time fatal, which is why no `*SeamTest.php` was added. **The corollary: stripping `#[\Override]` from either implementation silently removes the only thing protecting the interface declaration.**
- **Failures throw from one hierarchy, and growing it is not a breaking change (RSRMID-2895).** Every exception extends `CNIC\Exception\CnicException extends \Exception`. Reuse the existing types rather than duplicating them: `UnsupportedFeatureException` (a capability this platform or response does not have — since RSRMID-2919 also a cURL option or HTTP header the transport owns), `PaginationException`, `InvalidConfigurationException` (a configuration value out of range), `InvalidDateTimeException`.
  - **Additive by construction, which is the point.** Because everything ultimately extends `\Exception`, existing `catch (\Exception)` consumers keep working when a subclass appears — so a new failure mode needs **no** `BREAKING CHANGE:` footer and no major bump. That is what makes "add a subclass" the cheap option and a bare `\Exception` the expensive one: a bare throw is indistinguishable from a runtime bug at the call site and cannot be caught selectively ever after.
  - **Do not create ad-hoc exception types outside `CNIC\Exception`.** The failure modes are the SDK's public vocabulary; a type declared next to the code that throws it is invisible to a consumer writing catch blocks against the namespace.
  - Related: absence first, throw second, never a no-op — see the session-seam entry.
- **A public parameter name is public API, so renaming one needs a major (RSRMID-2935, breaking, v29.0.0).** Since PHP 8.0 a caller may bind an argument by name and the runtime floor here is 8.3, so consumers can already do it. PHP has no parameter alias, so there is **no deprecation path**: after a rename the caller gets `Error: Unknown named parameter $key` at runtime, with a message that does not point at an SDK upgrade. Every public parameter whose name carried no meaning was renamed in one batch for that reason; table in [MIGRATION.md](../../MIGRATION.md).
  - **A named argument binds to the *implementation's* parameter name, never the interface's** — verified on PHP 8.3.31, and the opposite of what an earlier revision of this entry claimed. Given `interface I { function get(string $columnName); }` and `class C implements I { function get(string $key); }`, a call through an `I`-typed variable accepts `get(key: …)` and rejects `get(columnName: …)`. **The consequence that matters: the implementation's names are the real contract, and typing against an interface does not insulate a consumer from an implementation rename.** Renaming only on the interface breaks no caller (only Psalm objects); renaming only on an implementation breaks callers while the interface looks untouched.
  - **The rename is what let the annotations go, and that was the point.** Meaningless names (`$value`, `$key`, `$id`, `$idx`, `$h`, `$r`, `$ph`, `$rr`, `$str`, `$rv`, `$uid`, `$pw`, `$secured`, `$toupper`) each needed a `@param` line restating them; 48 are gone. What deliberately **stayed** is every annotation encoding something a name cannot: an array shape PHPStan L9 requires (`array<string,mixed> $row`), a precondition on the caller (`$post` is "already masked"), the semantics of an empty string (`$proxy`/`$login`/`$session` reset), and one cross-brand fact (IBS's `generateTemplate()` `$code` goes on the wire as `status`). Do not delete those to make the count rounder. Follow-up to RSRMID-2934, which did the same for internal parameters and needed no major.
  - **A `protected` property name is extension API on the same terms**, and six were renamed alongside: `AbstractSocketConfig::$pw` → `$password`, `AbstractClient::$ua` → `$userAgent`, `$curlopts` → `$curlOptions`, and `AbstractResponse::$paginationkeys`/`$columnkeys`/`$columnindex` → camelCase (the repo's only violations of its own naming rule). The break is a *different* one and worth keeping distinct: a named argument is a caller concern, whereas a protected property is reachable only from a subclass — a narrower audience but a **louder** failure, an undefined-property access PHPStan reports at L9. Public properties were left alone: `$templates` and `ApiDateTime`'s readonly fields are accurately named, and `System::$name`/`$value` are native enum properties that cannot be renamed.
  - **A property reachable only by reflection needs the guard's string literal updated too, and that is a real trap.** `ClientConfigSeamTest` and `AbstractClientConfigDriftTest` reach these through `new ReflectionProperty(…, "curlopts")`. Neither analyser resolves those literals, so a missed one is invisible to `composer lint` and surfaces only as a `ReflectionException` under `composer test`. Note what was done to `ClientConfigSeamTest::CONFIG_OWNED_PROPERTIES`: the old spelling was **kept** alongside the new, matching the file's `socketURL`/`url` precedent, so re-adding *either* still fails. Renaming rather than adding would have quietly narrowed the guard.
  - **The guard is Psalm's `ParamNameMismatch`, not PHPStan — and the ticket said otherwise.** RSRMID-2935 recorded that PHPStan L9 reports `argument.parameterRenamedInSubtype`; only the conclusion was right. Renaming the interfaces and `src/` implementations while leaving four test transports and five test loggers on the old names left **PHPStan completely clean**; Psalm caught all 14. Both analysers cover `src/` **and** `tests/`, which is what made the test doubles visible at all — a reason not to narrow that scope.
  - **No `*SeamTest.php` was added, deliberately — but know where enforcement stops.** A reflection test comparing parameter names would duplicate `ParamNameMismatch`, which runs over every implementation the analysers *read* rather than a hand-maintained class list; `InterfaceCoverageSeamTest` compares `getNumberOfParameters()`, not names, and should not be grown into a name check. The blind spot is **scope**: the analysers read `src/` and `tests/` only, so the two places a rename actually got missed were `README.md`'s custom-logger snippet and `examples/CustomLoggerClass.php` — both consumer-facing templates, and `README.md` is the only doc that ships in the Composer dist. **Grep those two by hand when renaming a parameter.** What no tooling catches at all is the breaking act itself: renaming interface and implementations in lockstep leaves everything green. That one is policy, not a test — it is why this entry exists.
- **Sensitive-command masking is one algorithm and one field list per brand, not two of each (RSRMID-2938, non-breaking).** Which command keys are secret was declared four times — byte-identical within each brand across its `SocketConfig` and `Response` — and the masking algorithm twice, differing only by a null check; both docblocks said "Mirrors …", documenting the drift risk rather than removing it. `CNIC\CommandRedactor::redact(array $command, array $sensitiveFields): array`, a generic static method (`@template TValue of string|null`) modelled on the existing `CommandFormatter`, now holds the one matching algorithm — case-insensitive key comparison, values masked to `CommandRedactor::MASK`, `null` values left untouched — and both `AbstractSocketConfig::maskSensitiveCommand()` and `AbstractResponse::sanitizeCommand()` delegate to it. Each brand's field list is declared exactly once, in a new `CNR\SensitiveFields`/`IBS\SensitiveFields` holder class (`public const array KEYS`), and both the brand `SocketConfig` and `Response` initialise their `$sensitiveFields` property from that one constant instead of repeating the literal array.
  - **Rejected: sanitizing once on the `AbstractClient`/`SocketConfig` side and deleting `AbstractResponse::sanitizeCommand()`.** Both `CNR\Response` and `IBS\Response` are publicly constructible directly with a raw `$cmd` (`tests/CNR/ResponseTest.php` does exactly this to assert masking). If the Response stopped self-redacting, `new CNR\Response($raw, ["PASSWORD" => $real])` would store the real password — the client-side path never runs. Each hierarchy must stay independently safe; centralizing removal of either side's redaction is a leak, not a simplification, so **both existing call sites are kept, and only the algorithm and the field list are unified.**
  - **The base `protected array $sensitiveFields = []` properties on both abstracts are kept, not removed.** They are non-`final`, existing override hooks; deleting them would silently stop redacting for any downstream subclass already relying on one, turning a "non-breaking" ticket into a silent security regression.
  - **The `SensitiveFields` holder lives next to both consumers, not folded onto the brand `SocketConfig` for the `Response` to import.** That would save two small files but make a `Response` class reach into connection-config territory, against the grain of the RSRMID-2921 rule that connection state has exactly one home; a plain shared constant costs less than the precedent of a Response importing a SocketConfig-namespaced class.
  - **The unified algorithm keeps the config side's null-skip**, which is load-bearing there: `http_build_query()`/CNR's command builder both drop `null` values, so masking one would log a key the real request never sent. Carrying the skip into `sanitizeCommand()` changes one case unreachable through the public constructor's `array<string, string>` parameter type (`["PASSWORD" => null]`) — deliberate, not an oversight, and no secret is exposed either way.
  - **All three new classes are `@internal`, and that is a deliberate scope call, not an oversight of the `@psalm-api` rule.** CLAUDE.md says public API symbols get `@psalm-api`; these get the opposite tag because none of them helps a consumer talk to the API. `CommandRedactor` exists only to keep this SDK's own two masking call sites in step, and the `SensitiveFields` holders only to stop two literals drifting. The extension point consumers actually use is unchanged and still public: override `$sensitiveFields` on a subclass. Marking them `@internal` keeps them out of the published Doctum surface and out of the set of signatures a major bump has to protect — **so treat a change to `CommandRedactor::redact()`'s signature as non-breaking, which is the whole point of the tag.** They need no `@psalm-api` either way: both are referenced from `src/`, so `findUnusedCode` never reports them.
    - **The lint consequence, which is the part that will bite:** Psalm scopes `@internal` to the *declaring root namespace*, so every reference from `CNICTEST\` raised `InternalClass`/`InternalMethod` — 20 errors, because both `src/` and `tests/` are in `projectFiles`. Fixed by suppressing exactly those two issues for `../../tests` in `psalm.xml`, matching the `UnusedClass` entry already there; `src/` stays strict. **Rejected: a `@psalm-internal CNICTEST` line in the `src/` docblocks** — it would work (multiple `@psalm-internal` annotations are OR'd) but puts the test namespace's name in shipped production docblocks, and "the package's own tests may reach package internals" is a testing policy that belongs in the linter config, not in `src/`. PHPStan does not enforce `@internal` across namespaces at all and stayed clean throughout — do not read its silence as the annotation being inert. Note both suppressions are load-bearing under `UnusedIssueHandlerSuppression`: delete the last test that touches these classes and the *lint* breaks, not just coverage.
  - **No `*SeamTest.php` guard** — `tests/RedactionParityTest.php` pins that each brand's `SocketConfig` and `Response` defaults for `$sensitiveFields` are reflectively equal to each other and to `SensitiveFields::KEYS`, which is a value-equality check, not a structural seam, so it does not follow the guard-test docblock ritual. `tests/CommandRedactorTest.php` is `CommandRedactor`'s direct, brand-independent unit coverage — the redaction algorithm's first test surface of its own, previously reachable only through a brand config or response.
    - **MONIKER is asserted, not just asserted-in-prose.** `testMonikerInheritsTheIbsListRatherThanDeclaringItsOwn()` pins that `MONIKER\SocketConfig` still resolves to `IBS\SensitiveFields::KEYS` by inheritance — there is no `MONIKER\Response` and no MONIKER field list, and a MONIKER-local override that drifted from IBS would otherwise be the one drift this file's own anti-drift test could not see. Proven non-vacuous by adding `protected array $sensitiveFields = ["password"]` to `MONIKER\SocketConfig` and watching that test alone fail (the CNR and IBS cases stayed green, so the assertion is targeted rather than incidentally coupled).
- **The transport error is a declared parameter, not encoded into the payload (RSRMID-2937, breaking, v30.0.0).** `HttpTransport::post()` used to return the failure twice — as tuple element `[1]`, and as a `"httperror|"` prefix smuggled onto `[0]`, which `AbstractResponseTranslator::translate()` string-split back off with `explode("|", $newraw, 2)`. The sentinel is removed: `?string $error` is now an explicit trailing parameter, appended **last** and defaulted `null` on every hook in the pipeline (`TransportInterface::post()`'s tuple, `AbstractClient::newResponse()`/both brand overrides, `AbstractResponse::__construct()`/`translate()`/both brand overrides, `AbstractResponseTranslator::translate()`), so every existing positional call site keeps working. The two-level check is unchanged: `$error !== null` selects the `httperror` template, `$error !== ""` gates the `{HTTPERROR}` injection into it. `TransportInterface::post()`'s docblock now **states** the contract it always implied: a non-null `[1]` means `[0]` is unusable, and `HttpTransport` honours it by returning `["", $error]` on failure rather than any payload at all.
  - **`nocurl` is gone with the branch it existed for.** `curl_init() === false` is unreachable with `ext-curl` as a hard composer dependency; the guard is now `\assert($tmp !== false)`, matching the file's existing idiom, and the `"nocurl"` entry is deleted from both brand `ResponseTemplateManager::$templates`. Do not re-add it without a real reachable failure mode to attach it to.
  - **`AbstractResponseTranslator::resolveTemplateId(string $raw, ?string $error, array $templates): ?string` is the extracted decision point, and it is where the raw-as-template-id mocking route becomes explicit rather than incidental.** A non-null `$error` resolves to `"httperror"` **only if `$templates` declares that id** — `templates()` is an abstract hook, so a third-party brand translator's container need not include it, and indexing `$templates["httperror"]` unconditionally degrades an `Undefined array key` warning into a `TypeError` a few lines later. Otherwise `$raw` is checked against `$templates` and returned only if it matches — which is exactly what lets a test construct `new Response("empty")` or `new Response("nocurl-replacement-id")` (after `ResponseTemplateManager::addTemplate()`) and get a canned response with no real API round-trip. That lookup is the sanctioned mocking route CLAUDE.md names, not a leak of transport internals into response data; do not "fix" it by requiring a real API shape. `$templates` is a parameter rather than a second `static::templates()` call inside the method: `translate()` already binds one snapshot for the rest of its body, and resolving the id against a different call's snapshot than the one it is then dereferenced against is exactly the kind of inconsistency a registry-backed hook invites. The method must genuinely return `null` (an ordinary raw response, or an `$error` with no matching `"httperror"` entry) for PHPStan L9 to accept the `?string` signature — a version that only ever returned a string is flagged `return.unusedType` and is not just a style nit, it is evidence the null branch was never reachable.
